# 词声 · YTJ 语音默写

一个纯网页的英语词汇默写工具：上传或拍下单词和词组表，听英文释义或单词发音，把答案敲出来，自动判分并整理错题。

不需要安装 App，不需要登录，也没有后端服务。所有词库、成绩和照片都只在本机处理。

## 在线使用

已经部署到 GitHub Pages：

**https://realchenchenluo.github.io/cisheng/**

电脑和手机浏览器都可以直接打开。线上版本和本地版本功能一致；照片 OCR 所需的引擎和模型随网页一起发布，不会上传照片。

## 界面

- **深色 / 浅色双主题**：右上角太阳/月亮按钮一键切换，选择会保存在本机。
- **手机优先布局**：手机底部有固定开始栏，显示本次题量和预计时长，点一下就能开始；答题输入、拍照、设置都为触屏重新调整了尺寸。
- **拍照导入**：手机点“拍照 / 图片”会打开相机或相册；电脑上选择图片。
- 桌面端保留左右分栏，词库、成绩和测试入口都在首屏附近。

## 快速打开

**方式一：双击启动脚本**

双击 `启动词声.bat`。脚本会在本机启动一个静态网页服务，并自动打开浏览器：

```
http://127.0.0.1:8787/
```

使用期间保持那个黑色命令行窗口打开；关闭窗口即停止网页服务。

**方式二：直接开网页**

双击 `index.html` 也能使用核心功能。若浏览器限制本地文件的联网请求，改用方式一，或在项目目录运行：

```bash
python -m http.server 8787 --bind 127.0.0.1
```

然后访问 `http://127.0.0.1:8787/`。

推荐使用 Chrome 或 Edge。

> 注意：`http://127.0.0.1:8787` 和直接打开 `index.html`（`file://`）属于不同的浏览器存储空间，词库和成绩不会互通。建议固定使用同一种打开方式。
>
> 拍照识别建议通过启动脚本打开：浏览器会限制 `file://` 页面创建 OCR Worker，直接双击 `index.html` 时拍照识别可能不可用，文字上传仍然可用。

## 测试流程

上传文本或拍照导入词表后，系统会从词库中挑选条目，按三轮出题：

1. **词组释义**：播放 2–3 个词组的英文释义，你写出对应词组。
2. **单词释义**：播放 7–8 个单词的英文释义，你写出对应单词。
3. **单词听写**：播放 10 个单词的发音，你写出拼写。

每轮都可以重听、慢速播放、查看首字母提示。提交后立即显示对错、正确拼写、英文释义和中文释义。全部完成后会看到正确率、分轮成绩和错题列表，可以一键重练错题。

题量可以在“设置”里改为 2/3 个词组、7/8 个单词；听写固定 10 个。

### 出题偏好

- 优先选择较长、较复杂、带英文释义的条目。
- 词库条目右侧的星标表示“重点词”，会被优先抽到。
- 之前答错过的词，再次被抽到的概率更高（可在设置里关闭）。
- 听写会优先避开释义轮刚用过的单词；词量不足时才会复用。
- 词库数量不够时，测试会自动缩短，并在开始前提示实际题量。

## 导入词库

支持 `.txt` / `.csv` 文件、拖拽、直接粘贴，也可以拍照或选择图片。每行一条，推荐用 `|` 分隔：

```text
serendipity | The happy accident of finding something valuable. | 意外发现珍奇事物的能力
break the ice | To make people feel more relaxed. | 打破僵局
resilient | Able to recover quickly from difficulties. | 有韧性的
ubiquitous
```

也支持：

- Tab 分隔：`word	english definition	中文`
- CSV：`word,english definition,中文`（释义里有逗号时用英文双引号包住）
- 冒号：`word: english definition`
- 短横线：`word - english definition`
- 英文后直接接中文：`apple 苹果`
- 一行多个单词：`apple,banana,orange`

英文释义和中文释义都可以省略。没有英文释义的词不会进入前两轮，但可以进入听写。

项目里有一份可直接导入的示例：[`sample/sample-list.txt`](sample/sample-list.txt)。也可以点页面上的“载入示例”。

### 拍照 / 图片导入

1. 点“拍照 / 图片”，在手机上拍照或从相册选图；电脑上可以直接选择图片文件，也可以把图片拖进上传区。
2. 识别在本机完成。识别结果会先放进一个可编辑文本框，确认或修改后再导入词库。
3. 拍照时尽量拍正、光线均匀、只取词表区域；印刷体识别更准。中英文词表都可以尝试，中文释义会尽量保留。
4. 支持 JPG / PNG / WebP；iPhone 的 HEIC 照片建议先另存为 JPG。单张图片建议不超过 20MB。
5. 如果一页有多列，或一行被识别成了多个词，可以直接在识别结果里手动换行、删改。前两轮需要**英文释义**；如果照片里没有，导入后点“补全释义”联网获取，或手动编辑。

OCR 使用随项目附带的 Tesseract.js 和英文/中文模型，不需要登录，也不会上传照片。识别模型首次初始化需要几秒钟，之后会更快。如果一行识别得不对，直接改文本即可，不需要重新拍照。

## 补全英文释义

如果上传的词表只有单词或中文，可以点“补全释义”联网查询。系统会依次尝试：

1. [dictionaryapi.dev](https://dictionaryapi.dev/)
2. [Wiktionary](https://en.wiktionary.org/)
3. [Datamuse](https://www.datamuse.com/api/)

查询结果会缓存在浏览器里。自动获取的释义不一定完全贴合你的考试语境；可以点每条词右侧的编辑按钮，手动修改英文释义。只有具备可用英文释义的词才能进入前两轮。

## 语音说明

语音使用浏览器自带的英文语音合成（Web Speech API）：

- 建议佩戴耳机；释义只播报，不显示文本。
- 播报时会自动把释义里出现的答案词替换成 “blank”，避免直接泄题。
- 在“设置”里可以切换英文语音、调整速度、设置听写播报次数。
- Windows 如果没有英文语音，请在“设置 → 时间和语言 → 语音”里安装英语语音包，或使用 Chrome/Edge 自带的语音。
- 如果进入题目后没有自动播放，点一下页面上的扬声器按钮即可（浏览器可能拦截自动播放）。

## 数据与隐私

- 词库、设置、成绩、释义缓存全部保存在当前浏览器的 `localStorage`。
- 照片只在本机浏览器里用于 OCR，不会上传；OCR 引擎和模型已随项目本地提供。
- 没有账号、上传服务器或云端同步。
- “导出”会把词库导出为 CSV；“清空词库”只清空本机词库和释义缓存。
- 联网补全释义时，只会把单词本身发给上述公共词典接口。

## 常见问题

**没有声音？**  
先看“设置”里的英文语音是否可用；Windows 可在系统设置中安装英语语音包。也可以点“试听语音”。某些浏览器需要先点一下扬声器才会播放。

**自动播放被拦截？**  
这是浏览器的自动播放策略。点一次扬声器即可，后续题目通常可以正常自动播放。

**释义不准确或没有查到？**  
点词条右侧的编辑按钮，手动填写英文释义。自动释义来自公共词典，词义可能偏向其他语境。

**拍照识别不准？**  
OCR 对弯曲、反光、模糊的照片识别会下降。尽量只拍词表区域，保持光线均匀，优先使用印刷体。识别结果在导入前可以逐行修改；中文被识别成错字也可以直接改。

**点“拍照 / 图片”没有反应？**  
请用 `启动词声.bat` 打开网页，不要直接双击 `index.html`。同时确认 `vendor/tesseract/` 目录完整。第一次识别初始化模型需要几秒钟，进度条走完后才会出现文字。

**照片里明明有中文，为什么说缺英文释义？**  
中文释义会保存下来，但前两轮的“听释义写单词”需要英文释义。导入后点“补全释义”联网获取，或点词条右侧的编辑按钮手动填写。

**HEIC 照片无法识别？**  
浏览器不一定能解码 HEIC。请先把照片另存或转换为 JPG / PNG / WebP。

**CSV 打开是乱码？**  
请把文件另存为 UTF-8 编码。页面导出 CSV 时会自带 BOM，方便 Excel 打开。

**8787 端口被占用？**  
修改 `启动词声.bat` 里的 `PORT=8787`，改成一个空闲端口，再重新打开。

**能在手机上用吗？**  
可以，页面是响应式的。建议用手机 Chrome/Safari 打开同一台电脑的局域网地址，或将项目放到任意静态网页托管服务上。语音和联网释义能力取决于手机浏览器与网络。

## 释义来源与许可

自动释义来自 dictionaryapi.dev、Wiktionary 和 Datamuse，分别遵循其各自的服务条款与内容许可（Wiktionary 内容为 CC BY-SA）。内置示例词库中的释义为本项目自行编写，仅用于演示。

拍照识别使用随项目附带的 [Tesseract.js](https://github.com/naptha/tesseract.js) 5.1.1、[tesseract.js-core](https://github.com/naptha/tesseract.js-core) 5.1.1 和 [tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast) 的英文/中文模型，均为 Apache-2.0 许可。许可文件放在 `vendor/tesseract/` 中，详见其 `NOTICE.md`。
